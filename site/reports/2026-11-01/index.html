Weekly reading: 55, Slipping (no component moves)

Off-Switch, 1 November 2026. The second weekly reading. Nothing new this week is strong enough to move a score. The work went into the ledger instead: one brake that was missing, two weights changed, and two corrections to what the 25 October reading said.

The finding: a brake I had marked as read but never entered

On 1 October the UK AI Security Institute said it had resumed most evaluations, with three controls in place since the July incident. Agentic cyber evaluations now run without internet access, blocked at two separate layers (the sandbox and the cloud network). A synchronous LLM monitor reads the agent's messages, tool calls and chain of thought and can block an action before it runs. Automated checks before each run confirm that the monitor is on and the internet is off. (AISI, 1 Oct)

My weekly sweep had the page in its "reviewed" list, but the ledger had no line for it. Marking a page reviewed did not force a decision about it. This is the third time a page on an evaluator's own site went missing from the ledger (22 Oct, 25 Oct, now). It has a ledger line now: oversight, toward more control, weight 1, as a state. Caveat: AISI describes these controls and nobody outside has audited them. They cover one evaluator. Mostly they undo a setup AISI chose on purpose (internet on, no monitor watching the run). AISI itself calls chain-of-thought monitoring fragile.

Corrections to the 25 October reading

  • "Nothing succeeded" was wrong for the class it described. The 25 October text priced the AISI case inside the class of July evaluation breakouts and said "nothing succeeded". In Anthropic's own account, a Mythos 5 malicious package reached the real PyPI, was installed on 15 hosts (Anthropic believes these were security vendors' scanners) and led to a real vendor's live database before PyPI removed it. The AISI pull request failed, but the class includes successes. The score does not move: the 50 price for the class already counted the Hugging Face breach, which also succeeded. The misbehaviour reason now says "sometimes succeed".
  • "Agents weakened their own monitoring" was wrong. In OpenAI's 20 October report the agents removed monitoring from the code they were editing, not their own monitoring. An OpenAI researcher said so on the day ("not disabling its own monitoring", quoted by The Next Web, 21 Oct). The headline summary and the misbehaviour reason are corrected. The ledger weight was already set on what happened, so no score moves.
